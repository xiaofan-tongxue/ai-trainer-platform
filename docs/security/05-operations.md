# 安全运行管理制度与记录模板

文件状态：供运营单位审定发布的草案。编制日期：2026-09-14。批准人、发布日、适用部门、责任人和复审日期待填写。以下流程是拟执行要求，不是已执行证明。

## 1. 组织与职责

运营负责人对业务风险及资源负责；安全负责人维护风险台账和整改验收；系统/数据库管理员执行变更；审计人员独立复核操作与日志；数据负责人批准处理目的、范围、保留期限和第三方处理。高权限操作由实施与复核人员分离，避免一人申请、实施、验收全流程。当前单机开发账户尚未达到此分工，生产上线前落实人员与账号。

## 2. 账号与权限管理

账号实名关联实际责任人，禁止共享管理员账号。申请应列出角色、对象范围、用途和到期时间；业务负责人批准，管理员按最小权限开通，审计人员复核。初始/重置密码通过受控渠道交付，首次使用必须更新。上线前处置全部演示账号和已知旧密码。管理员通过MFA及受控管理入口访问，凭据不写入源码、命令行参数或工单附件。

岗位变更及时调整权限，离岗立即停用并撤销会话；按批准周期复核账号、数据库授权和服务身份。紧急权限须有事件编号、有效期与事后复核；发现越权、异常批量访问或凭据泄露时立即禁用/轮换相关凭据，保留证据。

## 3. 漏洞、补丁与变更

维护组件与资产台账，定期核查厂商公告和漏洞信息；按暴露面、可利用性、数据影响和现有控制评定优先级。高危或已被利用问题立即分析并采取临时控制，修复时限由安全负责人结合业务批准。禁止将生命周期结束组件长期视为“扫描无CVE即可安全”。

每次变更记录范围、差异、依赖、验证、停机窗口、加密备份和回退条件。数据库版本迁移必须先在独立环境验证，禁止直接覆盖共享实例。上线前复测认证、权限、CSRF、密钥不回传、读写与恢复；回退必须保证应用、数据库及密钥版本匹配。运行账号不授予DDL，迁移使用临时维护身份并及时回收。

## 4. 日志与监控

相关网络日志保存不少于六个月，实施受限访问和容量规划，依据事件保全延长相关记录留存；具体依据见[现行网络安全法](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)。统一可信时间源并记录时区。每天核验链完整性、固化末端摘要至独立存储，监控审计写失败、认证失败突增、429/403异常、异常管理变更、批量下载、密钥调用和备份失败。

日志查询需记录人员、目的、时间段与导出范围。导出数据脱敏，加密交付，到期清理。不要记录密码、Cookie、Authorization、API Key和完整作答内容。配置、锁定状态与审计记录不能无审批清理以掩盖安全事件。当前程序只提供加密日志与校验器，集中采集、告警响应和六个月实际留存须由运维实施。

## 5. 备份与业务连续性

备份范围应包含数据库结构及全部数据、应用与配置、题库/素材、审计日志和必要恢复材料。密钥与数据分权保管；至少一份离线或不可变且异地的加密副本。备份周期、保留期限及RPO/RTO根据业务批准，建议起点为每日数据备份、变更前备份、每季度恢复抽测；本建议不构成既有SLA。

恢复先在隔离环境验证解密、行数/关系、版本、权限和业务样例；真实恢复须授权并保留事故前副本。Windows DPAPI异机恢复依赖账号保护材料，必须完成演练，不得只复制.dpapi文件就认定可恢复。旧明文归档清理前核对加密副本、摘要、恢复身份与批准记录。

## 6. 安全事件应急预案

事件类别包括凭据泄露、越权获取、恶意代码、数据破坏、拒绝服务、审计中断和第三方API异常。按影响范围、数据性质和业务中断程度分级；应急联系人、替补、管理层和外部协调联系方式须在上线前填写并验证可达。

1. 发现与登记：记录发现时间、受影响系统、告警及初步影响，生成事件编号，冻结相关日志保留策略。
2. 控制影响：禁用失陷账号和令牌，收紧网关或隔离源站；怀疑密钥泄露时停止相关外发并评估轮换。避免删除日志或覆盖现场。
3. 取证分析：由指定人员保存访问日志、账号变更、配置差异和必要磁盘/内存证据；记录摘要、采集人、时间和保管链，控制真实数据接触。
4. 清除与修复：定位根因、修复漏洞、轮换失陷凭据、恢复可信构建。高权限身份失陷时不能仅重置用户密码。
5. 恢复与验证：隔离环境验证后受控恢复，复测原触发路径、授权边界和数据完整性，持续观察异常指标。
6. 沟通与报告：运营负责人依据实际事件、适用法规和主管要求确定报告与用户通知内容/时限；禁止编造“无需报告”的结论。
7. 复盘：输出原因、时间线、影响、处置、证据及改进，更新风险台账和培训内容。

## 7. 开发与第三方管理

代码审查覆盖鉴权、输入、SQL、文件路径、敏感输出、日志和依赖。测试使用合成数据，生产备份不得直接用于开发；确有必要时先审批脱敏。密钥泄露时轮换，不仅删除Git/文件中的文本。第三方升级固定版本、验证来源与完整性，保留组件清单和变更测试。

DeepSeek等服务应登记数据范围、处理目的、供应商约定、保存策略、接口地址、版本和应急退出方案。学员代码/文字可能主动包含隐私，提交前明确提示并按最少必要原则处理。禁止把用户隐私或API密钥写进提示词、测试报告或公开工单。处理目的变化需重新评估告知和授权要求。

## 8. 制度生效和复审

运营单位批准后发布并培训，按定期计划和重大事件/架构变化复审。用真实审批、巡检、培训、演练和复测记录证明执行；模板、计划或空白表格均不能替代执行证据。
