# 数据分类分级与密码应用实施方案

## 1. 分类原则与字段清单

以下为本项目内部工程分类，不等同于法定重要数据认定。正式认定由运营单位结合数据规模、内容、处理目的及主管部门要求完成。敏感字段实行应用层加密，关系元数据与公开课程字段按业务用途保留。字段加密不意味着整个数据库文件、内存或客户端均已加密。

| 数据表 | 已加密字段 | 内部分级/用途 |
|---|---|---|
| users | username、nickname、email | 受限：账号与联系方式 |
| settings | v | 机密/内部：含第三方API Key等全部配置值 |
| login_logs | username、ip、user_agent | 受限：认证追踪 |
| operation_logs | username、target、detail、ip | 受限：管理审计 |
| practice_records | user_answer、is_correct | 受限：作答表现 |
| exam_records | detail、score、total、correct、passed、duration_sec | 受限：考试成绩与答卷 |
| practical_submissions | content、score、analysis | 受限：代码、实操内容及反馈 |
| exam_sessions | paper、answers、result | 受限：试卷、答案、评阅 |
| learning_reports | report | 受限：学情推断与建议 |
| learning_profiles | exam_date、daily_minutes、foundation、institution | 受限：学习计划画像 |
| lesson_progress | score | 受限：课程成绩 |

共11表31列，代码清单为 `ProtectedFields.TABLES`。NULL表示不存在的数据，不转换为虚假密文。主键、外键、角色、账号/业务状态、时间戳、课程完成状态、错题计数等检索及关系元数据未做字段加密，仍可能反映学习行为，应依靠授权、最小权限和生产存储介质加密保护。课程/题库/素材是公开或授权教学资源，不因包含“答案”就等同身份隐私；接口仍按练习阶段控制答案返回。

| 其他资产 | 当前保护 | 剩余要求 |
|---|---|---|
| 登录密码 | PBKDF2不可逆派生，独立盐，600000轮 | 禁止回传/找回明文；通过重置流程处理 |
| 用户名检索索引 | 域分离HMAC-SHA256 | 等值关联可见；不能防同机密钥持有人查询 |

## 2. 加密格式与密钥管理

字段使用AES-256-GCM，随机96位nonce、128位认证标签，密文格式为 `ENC:v1:` 加Base64编码内容。AAD为 `表名.列名`，防止跨列替换而不绑定行主键；同列跨行替换不能单靠该AAD检测，应结合DB权限和审计，后续可在兼容迁移中加入行标识绑定。JSON序列化保存数值/文本类型，DAO读取时解密。

主密钥为密码学安全随机32字节，从DATA_ENCRYPTION_KEY或data-key.dpapi读取；环境变量优先。DPAPI依赖Windows账号和其保护材料，不是可任意跨机器复制的密钥文件。密钥库目录关闭继承，仅当前账号与SYSTEM具有访问规则。服务运行时必然会在内存中使用明文密钥，字段加密不能防已控制同一服务身份的攻击者。

`v1`表示序列化格式，不是已经实现多版本密钥轮换。禁止直接覆盖DATA_ENCRYPTION_KEY或data-key.dpapi；这会使既有数据不可读，影响用户名索引和审计链。当前未交付自动轮换工具。生产轮换必须保留旧版本解密能力，在隔离副本验证“旧密钥解密→新密钥重加密→重建检索索引→保留旧审计验证链→全量校验→切换”，经过变更审批与恢复演练再实施。

PBKDF2参数参考 [OWASP密码存储指引](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。加密方案与密钥隔离原则参考 [OWASP加密存储](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)及[密钥管理](https://cheatsheetseries.owasp.org/cheatsheets/Key_Management_Cheat_Sheet.html)。AES-GCM实现和DPAPI不构成商用密码产品认证或密评通过结论；应按GB/T39786及最终适用要求核定算法、产品、密钥服务与管理措施。

## 3. 迁移控制与已执行验证

SecurityMigration在停机维护窗口运行；先验证加密备份可解密，再变更字段类型并逐行加密，最终写入field-v1标记。MySQL5.7 DDL不具备整组事务回滚，数据更新使用事务；中断时必须保留密钥与现场，按同一版本幂等重试并核查结果。应用启动要求迁移标记存在，运行账号没有DDL权限。

数据库迁移备份包括13张用户/学习/配置表，不包含全部公共题库与素材，**不是完整灾难恢复备份**。57项隔离测试实际创建临时数据库，验证旧密码封装、字段密文、读写类型、迁移重入和将加密备份恢复到另一独立数据库；测试后移除临时库。恢复验证证明逻辑备份格式可恢复，不等于已演练整机损毁或异地故障接管。

当前应用目录备份与旧项目备份使用DPAPI加密并验证解密摘要。备份中的旧代码不得直接替换正在使用密文数据的新版；若回退必须恢复与旧版本匹配的数据库、密钥及应用，保持原始证据隔离。普通文件删除不能保证SSD、卷影副本、回收站、同步盘或旧数据页中的内容消失。

## 4. 运行生命周期

1. 采集：只收集学习所需字段，不主动收集身份证、银行卡等高敏资料；用户提交自由文本前明确禁止录入密钥和他人隐私。
2. 使用：依据会话主体、业务角色和对象归属读取必要字段；导出和批量查询应由业务负责人批准并留痕。
3. 传输：生产浏览器至网关使用TLS1.2/1.3；跨主机数据库连接验证证书；提供方仅官方HTTPS；加密备份使用受控传输。
4. 保存：网络日志不少于六个月；学情、答卷、账号资料期限需运营单位结合目的、法定义务和用户协议分别批准，不能默认永久留存。
5. 到期：经审核删除业务数据、派生报告和备份中到期副本，保留删除范围/执行/复核记录；法律保全期间暂停相关删除。
6. 恢复：备份、密钥与密码恢复材料分权保管，季度抽样恢复；完整灾备演练与RPO/RTO目标由业务审批后验证。
